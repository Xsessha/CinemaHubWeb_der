# Контрольні питання для захисту

## 1. У чому фундаментальна відмінність між Push Model та Pull Model? Чому Push Model безпечніша?

**Pull Model** означає, що рушій звітів сам підключається до бази даних і отримує дані. Для цього звіту потрібні налаштування підключення, а іноді й облікові дані.

**Push Model** означає, що застосунок сам запитує й за потреби фільтрує дані, а потім передає їх у звіт як `DataTable` або `DataSet`. У RDLC дані передаються через `ReportDataSource`, у Crystal Reports — через `SetDataSource`.

Push Model безпечніша, оскільки звіт не зберігає облікових даних бази даних і не виконує власні запити до неї. Доступ контролюється серверним кодом, де можна застосовувати параметризовані запити, перевірки доступу та мінімізацію переданих даних. Сам по собі Push Model не замінює авторизацію чи захист від SQL-ін'єкцій: ці вимоги все одно має забезпечувати застосунок.

## 2. Як у RDLC реалізувати умовне форматування за допомогою `IIf()`?

У виразі властивості `Color` або `BackgroundColor` використовують форму:

```vb
=IIf(умова, значення_якщо_істина, значення_якщо_хиба)
```

Наприклад, для кольору статусу оплати:

```vb
=IIf(First(Fields!PaymentStatus.Value, "TicketDS") = "Paid", "#2E7D32",
 IIf(First(Fields!PaymentStatus.Value, "TicketDS") = "Pending", "#F9A825", "#C62828"))
```

Вираз повертає зелений колір для оплаченого квитка, жовтий для очікування оплати та червоний для інших статусів. `IIf` може обчислювати обидва результати, тому вирази з діленням або іншими операціями, що можуть завершитися помилкою, треба захищати від некоректних значень.

## 3. Для чого потрібна подія `SubreportProcessing` у C#?

У локальному режимі RDLC підзвіт не має самостійного сервера звітів, який отримав би його дані. Подія `LocalReport.SubreportProcessing` дозволяє застосунку передати джерело даних кожному підзвіту під час його обробки. Обробник читає параметри підзвіту, наприклад `TicketID`, отримує відповідні рядки та додає `ReportDataSource` з ім'ям, яке збігається з набором даних у файлі підзвіту.

## 4. Які секції є у Crystal Reports і в якій послідовності вони виводяться?

Основні секції: **Report Header**, **Page Header**, **Group Header**, **Details**, **Group Footer**, **Report Footer** і **Page Footer**. Report Header і Report Footer зазвичай виводяться один раз на звіт; Page Header і Page Footer — на відповідних сторінках; Group Header і Group Footer — для кожної групи; Details — для записів групи.

Типовий потік вмісту сторінки: Report Header (на початку звіту) → Page Header → Group Header → Details → Group Footer → наступна група або Report Footer (у кінці звіту) → Page Footer внизу кожної сторінки. Точне розміщення секції залежить від розривів сторінки та налаштувань секцій; Page Footer закріплений за низом сторінки, а не є останнім елементом потоку даних.

## 5. Як у Crystal Syntax змінити колір шрифту залежно від значення поля?

У **Format Editor → Font → Color → x-2** задають формулу, що повертає значення кольору. Наприклад, для суми:

```crystal
If CurrentFieldValue >= 1200 Then crGreen
Else If CurrentFieldValue >= 600 Then Color(255, 140, 0)
Else crRed
```

У цьому прикладі значення від 1200 відображається зеленим, від 600 до 1199 — помаранчевим, менші суми — червоним. Пороги треба узгодити з масштабом даних звіту.
